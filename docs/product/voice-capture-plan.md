# 口說新增計畫（Phase 3）

狀態：**計畫，尚未實作**（分支 `feature/voice-capture`，預期獨立 PR）。本文件為版面重構（底部導覽決策見 [ADR 0006](../decisions/0006-unified-bottom-navigation.md)）中新增頁（Phase 3）的拆分細節。

---

## 1. 目標

- 「新增」頁（現 `/capture`）以**口說記帳**為主流程；手動填表、掃描、照片等其他方式降為附屬。
- 版面由上而下為**欄位區塊**（「一籃一籃」），狀態一目了然（已填入顯示值 / 待填灰底）。

## 2. 欄位區塊

- 頁面上方依序排列每個需要填的欄位區塊，**順序已定案**：`日期 → 類型 → 帳戶 → 類別 → 對象 → 品項 → 金額`。
- 每個區塊顯示狀態：已填入（顯示值）/ 待填（灰底）。

## 3. 兩種口說模式（頁內切換）

- **模式 A：整段口說**——使用者一次念完整筆（例：「7/25 中午和同事吃牛肉麵 480 現金」），系統解析後**自動填入對應欄位區塊**，使用者逐欄確認後存檔。
- **模式 B：逐步口說**——欄位**一個一個亮起**（含提示文案，如「請說金額」），使用者逐欄念出、逐欄填入，最後確認存檔。

技術基礎（可重用）：

- 模式 A 直接沿用 `AiLedgerPanel`：Web Speech API（`zh-TW`）把語音轉成文字 → AI 解析 → 草稿 → 使用者確認 → 寫入正式記錄（維持「AI 只產草稿、確認才算數」的既有邊界）。
- 模式 B 不需要 AI：語音辨識結果直接寫入當前亮起的欄位，離線/無 AI 金鑰時仍可用。
- 發票/收據照片、餐點照片、附件流程全部保留，只是降級為附屬入口（「其他方式」側邊/收合區）。
